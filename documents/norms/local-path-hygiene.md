# 本机路径与隐私卫生（公开仓库）

> **适用面**：全仓**所有**入库文本——代码、注释、`.cmd`/`.ps1`、md、配置、**提交信息**。体检 `[P]` 硬查：出现私人目录名或本机绝对路径即失败。
> **定位**：本篇只写「不许写什么 / 发现泄漏怎么处置」；脚本与 CI 的引用面另见 [`scripts-and-ci.md`](scripts-and-ci.md)。
> **事故背景**：2026-10-07 实测——本机用户目录与工作区绝对路径已随历史进入**公开**仓库，做了一次全历史脱敏重写（§5 有完整记录）。

## 1. 规则

1. **不写本机绝对路径**：仓库是 public，`<盘符>:\Users\<真名>\…`、`/Users/<真名>/…`、`/home/<真名>/…`、`<盘符>:\code\…` 一旦提交就进入**不可逆的公开历史**。
2. **该写什么**（按优先级）：
   - 代码：环境变量 / `os.homedir()` / `process.env.*` / 相对仓库根的路径；找不到就**明确报错**（附「怎么装、怎么配」），不要拿本机路径当兜底。
   - `.cmd` / `.ps1`：`%USERPROFILE%` / `%LOCALAPPDATA%` / `$env:…`。
   - md 与注释举例：`<用户>`、`<本地工作区>`、`<仓库根>`、`<盘符>` 这类**占位符**。
3. **工具内部路径只写仓库相对形式**：例如 `.workbuddy/memory/**`（已在 `.gitignore`）；不写它的绝对前缀。
4. **提交信息同样算**：`git log` 与代码一样公开——事故里 `C:/Users/<真名>/…` 也进过提交信息。
5. **判据与注释里也不许**：`TODO.md` 的「判据」列写 `git grep -n "C:/Users/"` 这种**模式**是允许的（体检 `[P]` 的占位符/不完整形式会放行）；写具体用户的真路径不允许。

## 2. 为什么（不是洁癖）

- 仓库 public ⇒ 历史一旦推上去，**删工作区文件不会让它消失**（`git log`、镜像、第三方索引里都还在）。
- 「一步步泄漏」：每个 agent 各自加一条本机路径都不显眼，累积起来就是一份本机环境地图（用户名、目录布局、装了哪些工具链）。
- 泄漏面不止代码：注释、md 举例、提交信息、判据、`.cmd` 里的兜底路径都算。

## 3. 体检 `[P]` 与自检

```bash
node src/scripts/check-doc-drift.mjs    # [P] 本机路径 必须 0
git log --all --oneline -- <改动过的文件>   # 确认它没在历史里被提交过（体检只保当前树）
```

`[P]` 豁免：`<用户>` / `<本机用户>` / `<本地工作区>` / `<仓库根>` / `<盘符>` / `<真名>` / `%USERPROFILE%` / `$env:USERPROFILE`。

## 4. 发现泄漏后的处置（三步，缺一不可）

1. **当前树**：按只读/可编辑走 `approve → 改 → sync`（见 `AGENTS §0.2`）。**这一步不解决历史。**
2. **历史**（只有确实进过提交才需要）：
   - **先整体镜像备份**：`git clone --mirror . .tmp/pre-rewrite.git`（`.tmp/` 已 gitignore）。
   - 记录重写前的提交序列（供 §4.3 做 SHA 重映射）：`git rev-list --reverse main > .tmp/main-before.txt`。
   - 用**索引过滤器**只换 blob：`git filter-branch --index-filter '<替换脚本>' --tag-name-filter cat -- --all`。
     - 脚本先扫**全仓所有 blob**、只对命中的 `git hash-object -w`，把「旧 blob → 新 blob」存成映射；index-filter 里只按映射改索引（不要每次读全树）。
     - `filter-branch` 把原 ref 存进 `refs/original/*`（本地可回滚）；`--tag-name-filter cat` 让 tag 跟着重写。
   - **校验**：把 `main` + tag **可达的所有 blob** 粗读一遍确认 0 命中；再确认 `git diff <旧HEAD> <新HEAD>` 为空（只该改历史，不该改当前内容）。
   - **强推**：`git push --force-with-lease=refs/heads/main:<旧SHA> origin main`，tag 单独 `git push --force origin v0.1.0`。
3. **连带义务（重写一定换掉所有 SHA）**：
   - 文档里的短 SHA 必须重映射：用**位置对齐**建立映射——`git rev-list --reverse main` 重写前后条数相同、顺序不变，逐条比对 `%at|%s` 应**全部相等**（实测 403/403 相等 ⇒ 映射可信）。
   - 已被 `--amend`/rebase 淘汰、只躺在对象库里的旧 SHA：按「**作者日期 + 主题 + 作者**」在新历史里找回（实测 5 处找回、1 处无处可找 ⇒ 改为文字描述，不再引用 SHA）。
   - **提交信息里引用的历史 SHA 无法救**：任何全历史重写都会让它们失效，重写前必须跟 owner 讲清——这是既定代价。
   - 第三方（fork / 镜像 / 平台的不可达对象缓存）不受我们控制：`--force` 只保证「refs 不再指向旧历史」。

## 5. 事故记录（2026-10-07，第一次全历史脱敏）

- **被泄漏的串**：`C:\Users\<真名>` / `C:/Users/<真名>` / `/Users/<真名>`（含其后 `.workbuddy/binaries/node/workspace/node_modules/ws/index.js` 一类工具路径）；`<盘符>:\code\projects\websurf`（含 `-cleanup-backup-2026-09-12` 等分支目录）。
- **怎么进来的**：`smoke-cdp.mjs` 的 `ws` 兜底路径（`T-132`，2026-09 起就在 `origin/main` 上）；早期 `.cmd` 里的绝对路径；老文档、老 `AGENTS.md` 里的本机工作区路径；一条进展记录逐字引用。
- **影响面**：公开仓库 `github.com/<owner>/websurf`；历史 blob 里 **90 个**含泄漏串——其中一部分在本次推送**之前**就已公开。由「推送前文件统计」发现（工作树已 0 命中，但历史仍在）。
- **处置**：全历史 `filter-branch` 索引过滤重写（417 提交 / main + tag + 本地分支 + stash）→ 校验「main+tag 可达 blob 0 命中」「新 HEAD 树与旧 HEAD 逐字相同」→ 文档 **73 处**短 SHA 按位置映射改写、1 处改为文字 → 强推 main 与 tag。
- **残留（已知且接受）**：重写前的提交对象在平台上不再被任何 ref 指向，但可能在其不可达对象区保留一段时间；已被 fork / 被第三方镜像复制的副本不受我们控制。**提交信息里对旧 SHA 的引用（实测 170 处）已失效。**

## 6. 教训（每条都付过代价）

1. **写路径前先想「这条会不会进公开历史」**：兜底路径、示例、注释、判据、提交信息都算。
2. **`git commit --amend` 会让已写进文档的 SHA 失效**：本次实测 5 处文档引用了被 amend 淘汰的提交。写 SHA 前先确认它在 ref 上（`git merge-base --is-ancestor <sha> main`）。
3. **体检只保当前树**：`[P]` 拦不住「先提交再删」；改完还要 `git log --all --oneline -- <文件>` 确认它没进过历史。
4. **删文件 ≠ 删历史**：进了历史只有「重写 + 强推」这一条路，代价是**所有 SHA 都变**。
5. **脱敏要连记录一起脱**：进展记录逐字引用泄漏串，等于换个地方再公开一次。
