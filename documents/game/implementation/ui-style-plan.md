# implementation / UI 风格改造计划（`apps/game/web`）

> 立项：2026-09-29。owner 反馈「现在的 game 太像廉价网页游戏，没有质感；整体观感应当接近
> LBEILC/RhineLabUI 的风格，但不要照搬」。本文只做**分析与计划**，改码按 P1→P4 分期推进。
> 事实来源：本仓库当前代码 + RhineLabUI 公开仓库（`https://github.com/LBEILC/RhineLabUI`
> 与其 `DESIGN.md`）；凡本文引用的外部色值/参数，均标注出处，改码时按「暗色适配」落地。

## 一、目标与非目标

**目标**：把 `apps/game` 的界面（ESC 控制面板 + HUD 覆盖层 + 加载卡）从「默认表单控件的网页小工具」
提升为「有一致几何秩序与材质层次的暗色精工界面」——细线、刻线、压槽、嵌件、等宽读数、克制运动。

**非目标**：
- 不做 RhineLabUI 的像素级复刻（它是 3D 档案终端，我们是 3D 游戏上的 HUD，信息密度与场景关系不同）；
- 不改 JS 行为与契约：CSS 变量名（`--ch-color`/`--ch-size`/`--ch-thickness`/`--ch-gap`/`--load-pct`）、
  DOM id、JS 生成的类名（`savepoint-row`/`key-chip`/`key-row`/`kempty`/`health-log`）**一个都不动**（契约见
  `apps/game/web/styles.css:15`-`:24` 的头注）；
- 不引入前端框架、不引入动画库（对照 RhineLabUI `DESIGN.md` 的禁止项：不引入新的前端/动效设计方法）；
- 不引入网络字体依赖作为硬要求（默认走系统字体栈，自托管字体列为待裁决项）。

## 二、现状诊断：廉价感的六个来源（逐条带证据）

| # | 问题 | 证据 | 为什么显得廉价 |
|---|---|---|---|
| 1 | **强调色是纯黄 #f5c518** | `apps/game/web/styles.css:39` | 高饱和塑料黄；RhineLabUI 暗色用的是**琥珀 #c5a16b**（`DESIGN.md`：暗色 `#c5a16b 为琥珀强调`）。色温与饱和度是"质感"的第一杠杆 |

| 3 | **控件全是浏览器原生件** | `:319` range 只改 `accent-color`、`:339` checkbox 原生、`:350` select 原生、`:343` color 原生 | 一眼"默认表单"。RhineLabUI 的控件全部自绘（细线轨道 + 刻度 + 嵌件游标） |

| 5 | **装饰是"贴上去"的孤立图形** | `:212` 顶边黄块、`:228` 螺丝、`:239` 六边形徽记、`:278` 切角 | 每个都是单独伪元素，彼此无几何关系；RhineLabUI 里螺丝在**压槽内**、黄块是**真实嵌槽**（`DESIGN.md`：黄色嵌片与盖板齐平并建立真实嵌槽、螺丝只保留右上和左下、带十字凹槽与齐平垫圈） |

远低于 44px 触控基线。

## 三、从 RhineLabUI 提取的可迁移语彙（暗色适配版）

| **细线 + 紧凑排字** | "界面以细线和紧凑排字组织" | 全站 1px 发丝线；分隔优先用线而不是色块；取消导航色块 |
| **压槽 / 内周边 / 刻线** | "顶部双边压槽、盖板前沿细阶、内周边与接缝" | 窗口顶缘做 1–2px 内凹压槽线；面板内各小节用刻线分隔而非色块 |
| **嵌件（黄块）** | "黄色嵌片与盖板齐平，并建立真实嵌槽" | 把现有"顶边黄块"改成**嵌在顶缘压槽里**的短嵌片（不再是浮在上的方块） |

| **等宽读数 + 滚动编号** | 编号 `X-001` 三位前导零、460ms 滚动 | 读数（帧率/速度/百分比）统一等宽 + 单位；编号类加前导零（静态即可，动效见下） |

**明确不迁移**：3D 档案阵列与相机运动、玻璃解密前沿、白底开场、原片逐帧复刻、MiSans 品牌字样排版。

## 四、分期计划（P1–P4）

> **状态（2026-09-29）**：P1–P4 已由另一执行者落地并提交（`92dd487`：
> `style(web): game 莱茵精工 P1-P4 落地——琥珀暗色规格 + 控件自绘 + 壳体材质 + HUD 铭牌`）。
> owner 复核截图后判定「仍不够菱角分明、装饰堆砌没有设计语言、布局失衡」⇒ **开第二轮返工 R1，
> 要求见 §八**。本节保留原始分期口径，作为已完成部分的验收依据。

### P1 · 令牌与排版基线（不动结构）
- 换 `--accent` 为琥珀系、底/正文/辅助/分隔整体改为暖灰暗色系（`styles.css:30`-`:45`）；
- 建立字号/字重/字距三级：面板正文 14px、读数 12px 等宽、小节标题 12px/600 + 0.06em 字距；
- HUD 读数与面板读数字体统一为 `var(--mono)`，数值补单位与刻度。
- 验收：视觉上"冷+塑料黄"消失；`--ch-*`/`--load-pct` 变量名不变；`npm run typecheck` 不受影响（纯 CSS）。

### P2 · 控件自绘（廉价感的最大来源）
- `input[type=range]`：细线轨道（2px）+ 琥珀游标（方角嵌件）+ 轨道刻度；保留 `accent-color` 作无障碍回落；
- `input[type=checkbox]`：改为 16px 方框 + 1px 边 + 方框内琥珀方块（checked）；`appearance:none` 自绘；
- `select`：保留原生下拉（可靠）但改外观——细线框 + 右侧刻度箭头 + 聚焦态琥珀边；
- `input[type=color]`：改细线小方块 + 内嵌 swatch，去掉原生内边距；
- 主按钮 `.map-btn`：高度 ≥40px，保留右上 12px 切角，切角改为"斜切 + 内刻线"而非纯 clip。
- 验收：四类控件在 Chrome/Edge 下无原生件外观残留；键盘可达（`:focus-visible` 仍在）。

### P3 · 壳体与材质层次
- `.win`：加顶缘压槽（内凹 1px 线）+ 内周边（inset hairline）+ 分区刻线；黄块改为"嵌在压槽里的短嵌片"；
- `.nav`：导航项去掉色块，改为左缘刻度条 + 激活态刻线；螺丝加垫圈环；
- `.body`：小节用刻线分组；`.row` 行间加 1px 分组节奏（不靠 hover 色块表达结构）；
- `.load-card`：与 `.win` 同一套壳体语彙（压槽 + 螺丝 + 进度轨道刻线）。
- 验收：面板与加载卡看起来是"同一台设备的两个面板"，而不是两个网页弹窗。

### P4 · HUD 统一与收尾
- `#fps`/`#status`：统一为"铭牌"形态（等宽读数 + 左缘/上缘刻度 + 刻线边框），与面板同源；
- `#stats`：加单位与次级刻度行（保留现有 tabular-nums 与 text-shadow 可读性处理）；
- `#keys`：键帽改为细线方框 + 激活态琥珀内嵌（保留 grid 位置与 `data-action` 不变）；
- 全量走查：禁用词/行尾/BOM/CRLF、`apps/game` typecheck、起 dev 服务人工过一遍七个模块页。

### 8.1 截图复核：七条具体病症（对象 = `92dd487` 版「人物体型」页）

### 8.2 几何规范（菱角分明，硬性）

| 项 | 规范 |
|---|---|
| 圆角 | **一律 0**。唯一允许的圆是"硬件件"：螺丝与服务孔（`border-radius: 50%`）。`--r` / `--r-lg` 应退化为 `0`（或直接删除令牌并要求显式写 `0`） |
| 切角（菱角） | 全站只用**一种**切角：尺寸 `10px`、方向**右上**（`clip-path: polygon(0 0, calc(100% - 10px) 0, 100% 10px, 100% 100%, 0 100%)`）。使用范围限定三类：主按钮、标签条（chip 的激活态）、面板窗口**右上角**（与螺丝同位，形成"硬件 + 切角"的组合读法） |
| 刻线系统 | 三种线宽固定：`2px`（结构线：窗口顶缘、激活左条）、`1px`（分隔：节点、行组）、`1px 点线`（引导线：字段 label → 值，用 `repeating-linear-gradient` 每 4px 1px） |
| 压槽 | 窗口顶缘做**真实压槽**：外侧 1px 亮线 `rgba(255,255,255,0.06)` + 内侧 1px 暗线 `rgba(0,0,0,0.55)`，黄块嵌在压槽上（齐平，不是浮起） |

### 8.3 档案质感元素（新增，必须成套出现）

| 元素 | 规格 | 出现规则 |
|---|---|---|
| **档案编号** | 等宽 12px，格式 `<分类码>-<两位序号>`，如 `BD-01`；置于页头标题**右上**，与切角同侧 | 每个 pane **恰好 1 处** |
| **字段引导线** | label 与值之间用 1px 点线填满空隙（`flex: 1` 的点线块） | 每一行**都**有（这是"档案表"的核心读法） |
| **单位与读数** | 值列固定 `88px` 右对齐等宽；单位（`Hz` / `u/s` / `°` / `HU`）以 11px muted 紧随 | 有物理量的行都必须带单位 |
| **分组刻度尺** | h4 标题右侧接一条 1px 刻线，末端 3px 短竖刻度 | 每个 h4 **都**有 |
| **状态标签条** | 12px 高、无圆角、1px 边；三态：默认（边 muted）/ 激活（琥珀边 + 琥珀字）/ 禁用（45% 透明） | chip 类（键位、模式按钮）统一用它 |
| **页脚署名位** | 右下角 11px muted 小字，内容 = pane 名 + 版本短码 | 每个 pane **都**有（填补底部空白，见 8.4） |
| **硬件件** | 螺丝 9px（十字凹槽 + 垫圈）**恰好 2 处**（窗口右上、加载卡左下）；服务孔 5px 圆 **恰好 1 处**（窗口左下，与右上螺丝对角） | 计数固定，不得增减 |

### 8.4 布局修正（治"怪怪的"）

1. **窗口高度改为内容驱动**：`height: 580px` → `height: auto; min-height: 520px; max-height: 92vh`，内容少时不留空白；内容多时由 `.body` 滚动。
2. **行网格统一为三列**：`grid-template-columns: 168px 1fr 88px`（label / 控件 / 读数），label 不再用 `flex: 0 0 128px`。
3. **取消"同值双控件"的重复感**：滑块右端的 `.val input` **去边框**，改为「读数区」——等宽右对齐文本 + 单位，仅在聚焦时可编辑（保留原 id 与 JS 契约）；视觉上读作"刻度 + 读数"。
4. **次级按钮归位**：`恢复默认` 等放在读数列对齐（右对齐），不再落在空 label 之后居中；空 label 的行改为 `grid-column: 2 / -1` 居右。
5. **关闭按钮**改为"刻线分隔 + 文字项"（去掉全宽线框），或移入页脚署名位右侧。
6. **页脚收尾**：内容不足时用"页脚署名 + 分组刻度尺"收尾，而不是留白。
7. **导航宽度**：180px → 168px（与行 label 列同宽，形成竖向对齐），导航项高 36px（触控/点击基线）。

### 8.5 设计语言收敛规则（本次返工的核心）

> 症结不是"元素不好看"，而是**每个装饰只出现一次**，因而读不出规律。返工必须让元素"成群出现且位置可预期"。

- 元素只允许分三层：**结构层**（框 / 压槽 / 刻线 / 引导线）、**嵌件层**（琥珀块 / 游标 / 标签条 / 切角）、**硬件层**（螺丝 / 服务孔 / 编号）。
- **每个元素在同屏出现次数 ≥2，且位置遵守固定规律**；只有 1 处的装饰**必须删除或补成对**。
- 琥珀（`--accent`）全屏**最多 5 处**：主按钮底、激活导航左条、滑块游标、页头编号、窗口顶缘嵌片。超出即视为噪音。
- 状态一律用**刻线 + 嵌件**表达，不用色块填充。

### 8.6 R1 禁止项（给执行者）

1. 不允许出现圆角（螺丝/服务孔除外）；
2. 不允许"每个装饰只出现一次"的孤立元素；
3. 不允许同值滑块与输入框并列成"两个输入框"的读法；
4. 不允许用色块表达选中/激活状态；
5. 不允许新增第 4 层语言（现有 5 种装饰要**收敛**到 3 层，不是再加）；
6. 不允许改动 JS 契约（`--ch-*` / `--load-pct` / 全部 DOM id / JS 生成类名）；
7. 不允许引入动效/字体依赖（R1 仍为静态；D1/D2 未裁决前不开放）。
