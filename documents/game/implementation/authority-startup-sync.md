# 权威线启动同步（出生点下坠缓慢）

> 落点：`test/game-core`（绝对隔离工程，仓库根 `src/` 零引用，见 [AGENTS.md §2.1](../../../AGENTS.md)）。
> 主题：主线程**预测线**与 Worker **权威线**在"地图刚加载完"这段窗口里的耦合缺陷。
> 事实基准：2026-09-20 实机（headless + CDP 出帧）复现与复核。

## 1. 用户口径与观察

- 「在出生点下坠很慢，只有落地一次之后下坠才正常」；
- 用户补充的关键观察：**渲染侧（预测）先落地，权威计算过一会才"载入"**。

## 2. 机制（两段耦合，都会按住下坠）

架构：Worker 权威线加载地图碰撞（world-json → PhysWorld）并自驱 64Hz；主线程是渲染预测线，
每帧 `correctFromAuthority()` → `calibrateVelocity()` → `predPhys.tick(dt)`，**权威是速度之主**。

| # | 位置 | 缺陷 |
|---|---|---|
| A | `authority-calibrator.ts` `calibrateVelocity()` | **无条件**把权威速度写进渲染物理。Worker 建世界期间权威仍停在出生点、`vel = 0` ⇒ 渲染每帧刚被重力加速起来就被改写回 0 ⇒ 下坠几乎不动（实测拦下 **129 帧**） |
| B | 同文件 `correctFromAuthority()` 的 `!predStarted` 分支 | 首帧**用权威全状态 `set_state` 覆盖渲染**（位置+速度+onGround）。首帧来迟时，这条把已经掉下去的渲染**拽回出生点并清零速度** —— 实测首帧到达时渲染已领先 **288 HU**（≈0.6s 自由落体） |

⇒ 合成症状：渲染先掉一段 → 被首帧拽回出生点 → 之后又被权威的静止速度按住 ~400ms →
权威线自己也开始掉、追上后恢复 ⇒ 用户看到的"下坠很慢、落地一次后才正常"。

## 3. 修法（都只动"未建立"窗口，不改稳态语义）

1. **权威建立闸门**：连续 `AUTH_LIVE_FRAMES = 8` 条**前进**的权威帧（按发布版本号 `V_A` 递增判定）
   且距首帧 ≥ `AUTH_LIVE_MS = 400ms`，才允许速度写入；此前纯预测。
2. **陈旧保护**：`now − authArrivedAtMs > AUTH_STALE_MS = 300ms` 时不再拿旧速度写渲染。
3. **首帧起点校准加漂移门**：`|渲染 − 权威| > START_MAX_DRIFT_HU = 64 HU` 时**不回拉**渲染
   （与硬约束「渲染位置永不被校正」一致），改由既有的 `routineReanchor`（每帧执行）把渲染
   当前状态推给权威，让权威从玩家真正所在位置继续算。
4. 建立/跳过都打 `console.info` 量化上报（见 §4），面板可经 `authorityStatus()` 读快照。

## 4. 实测（headless，surf_666，修复后）

```text
+20.82s [authority] 首帧起点校准**已跳过**：渲染已领先 288 HU（首帧来迟，权威侧仍在出生点静止态）⇒ 不回拉渲染，改为把渲染状态推给权威
+21.22s [authority] 权威线已建立：首帧后 403ms（前进帧=28）；此前 129 帧按纯预测处理（未把权威速度写进渲染）
```

- 首帧落后量 **288 HU**：修复前这 288 HU 的下坠会被一次 `set_state` 抹掉。
- 建立耗时 **403ms / 129 帧**：这段窗口内修复前每帧都在把权威的 0 速度写进渲染。
- 回归：`test:phys` 五指纹全绿（gravity −12.50/tick、landing tick31、jump 289.49、
  crouch 46.04、teleport tick24）、`typecheck` 0。

## 5. 未做 / 待确认

- **为什么首帧迟到 ~0.6s**：Worker 侧构建碰撞世界 + `world-json` 传输的耗时尚未单独度量
  （现有日志只给到"首帧到达"这一时刻）。下一步可在 Worker 侧加"世界就绪"上报，
  把"构建"与"首帧"两段分开计时；那时才能判断是否有优化空间（而不是靠客户端猜测）。
- 用户机位复测：同一行日志会打印他机器上的首帧落后量与建立耗时。
