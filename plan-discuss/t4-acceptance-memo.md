## 0. 结论摘要

1. **「忠实反映」可以收敛为一个可执行的逐帧等式（P0/L0 弦插值）**：渲染值必须等于「已发布 tick 状态对」的插值函数值，除此之外对状态量的任何变换都违规。历史插值的边界 = α∈[0,1] 且两端点都是已发布的真实 tick 状态；α>1（外推）、预测实例、渲染侧速度积分、任何平滑滤波全部禁止。兜底是「冻结在最后真实状态」而不是「猜未来」。
2. **当前两模式的渲染消费都在违背前提②**：耦合模式跑渲染侧预测实例（`game/src/renderer/renderer-main.ts:954`，变步长 tick + 校准）；解耦模式的「纯消费」实为一阶线性**外推**（未来预测，`authority-calibrator.ts:110-120`，`renderer-main.ts:1038`）。这不是实现瑕疵，是两种模式的构造性选择；第三模式的验收草案正是要把它们判为不合格。
   **【r2 背景定论，收敛产物必带】**（captain 已确认）：用户 r2 裁定「不要任何渲染推定」的当前现状是——现行解耦模式的渲染通道（extrapolateAuthPose：pos + vel×dt）**恰恰就是这个裁定的违例本尊**，耦合模式则是第二违例（渲染侧预测实例）。因此方案 v2 的历史插值（只回放真实历史）不是锦上添花的新增平滑，而是**对前提②的首次真实落实**；t5 收敛时此论断须作为「为什么插值方案不是又一个渲染推定」的直接回答写入 v2 背景节。
3. **异常判据给出四层（A1 硬减速 / A2 记账恒等 / A3 意外碰撞 / A4 意外运动）+ 事件白名单**，阈值全部从内核公式推出（friction=4、g=800、dt=1/64、DIST_EPSILON=0.03125、STEP_HEIGHT=18、锚定距离 64 HU），可由下一团队的 node+wasm 模拟台逐条自动化（node 加载 wasm 已有 11 个先例脚本）。
4. **五维对比（复杂度/输入延迟/确定性/边缘行为/维护成本）逐维给出度量方法**，三模式现状全部有代码证据：耦合与解耦在全部五个维度都被「双实例互写」拖累；单实例 tick 在确定性/边缘行为/维护上结构性占优，唯一实代价是 +1~2 tick（16~31ms）恒定可见延迟——这是必须交用户裁决的分歧点，不是团队可自决项。
5. **三关口验收节奏细化**为可判定的 exit criteria（Gate 1 本团队、Gate 2 矩阵数据、Gate 3 终审前）。

## 1. 「忠实反映」的可测验收定义

### 1.1 定义本体（验收总式）

设 worker 单实例按确定性网格发布 tick 状态序列 S = {S_k}，S_k 含 pos、vel、yaw、pitch、eyeHeight、onGround、**tickIndex k**、**due 时刻 t_k = T0 + k·tickDt**（tickDt=1/64）。渲染帧 r 在主线程墙钟时刻 w 渲染，则：

```
τ   = w − anchor − Δ            （Δ = 插值延迟，缺省 1 tick + 4ms 守卫）
(k−1, k) = 满足 t_{k−1} ≤ τ < t_k 的最近已发布 tick 对
α   = (τ − t_{k−1}) / tickDt    （α ∈ [0, 1)）

渲染位置  pos_r  = p_{k−1} + (p_k − p_{k−1})·α
渲染偏航  yaw_r  = 最短弧插值(yaw_{k−1}, yaw_k, α)   （wrap 感知）
渲染俯仰  pitch_r = pitch_{k−1} + (pitch_k − pitch_{k−1})·α
渲染眼高  eye_r  = eye_{k−1} + (eye_k − eye_{k−1})·α
```

**验收断言（P0）**：对每一渲染帧，|实测渲染值 − 上式| ≤ 容差。位置容差 1e−3 HU，角度容差 1e−3°（float64 下理论残差 ~1e−12，容差留给工程噪声）。α 必须满足 α < 1 + 1e−9——**任何 α>1 的帧直接判 FAIL**（外推=预测未来）。

**为什么弦插值是「忠实」而不是「推定」**：tick 内位移由扫掠碰撞给出，从 p_{k−1} 到 p_k 的运动在无碰撞段就是直线（`src/phys/world.rs` trace 的端点插值语义）；弦插值回放的正是物理自己走过的那条线段。tick 角点处的折弯（64 边形的顶点）被原样保留——这正是用户洞见④要求拟合的「tick 计算本身的速度行为」。任何超出弦的修圆（贝塞尔/弹簧/低通）都是渲染推定，禁止。

### 1.2 允许 / 禁止清单（渲染消费侧）

**允许（且仅允许）**：
1. 两个**已发布** tick 状态之间的插值（α∈[0,1)），端点只来自权威发布；
2. 下一 tick 未及时发布时的兜底：**冻结在最后已发布状态**（α 钳 1），并计一次 starvation 事件（这是诚实的卡顿，不是用预测掩盖）；
3. 角度 wrap 感知的最短弧选择（数学惯例，非平滑）；
4. 度→弧度换算、眼高加成到相机（`renderer-main.ts:970-971` 同款换算）。

**禁止**：
1. 渲染侧持有/推进任何 PhysWorld 实例（含 predict——`mod.rs:275-295` 的 predict 通道在第三模式应下线）；
2. 任何形式的外推：pos + vel×dt（解耦现状，`authority-calibrator.ts:113-115`）即便加了加速度项也不行——加速度项仍是模型推断，不是已算出的值；
3. 渲染侧速度积分、位置修正、吸附、回滚（校准器四件套在第三模式整体废弃）；
4. 任何平滑滤波（EMA/低通/弹簧/缓动）作用于状态量；
5. α 的时间基准使用发布墙钟抖动量（见 §1.3 缓冲策略）；
6. 对物理值做「看起来更顺」的任何变换，包括插值端点选择跨 tick（一次只用相邻对）。

### 1.3 历史插值的允许边界（协议级）

- **端点合法性**：两端点必须是 worker 依 tick 网格算出的真实状态；禁止渲染侧「重算」或「估计」端点。tick 状态一经发布不可变（双缓冲 release 语义已满足，`shared-state.ts:492-511`）。
- **α 时钟**：τ 用**确定性 tick 网格**（T0 锚 + k/64），不用发布时刻 timeMs 的抖动值。理由：发布时刻含 setTimeout(4ms) 驱动抖动（`auth-loop.ts:203`），若 α 跟随发布墙钟，发布抖动会直接变成画面抖动；用网格则发布抖动只影响「那格是否已可用」，不影响已可用格的插值位置。锚定方式二选一（team 自决）：协议加 tickIndex+dueMs（512B 尚有余量，耦合槽区用至 288B），或消费侧由首帧 timeMs+tick 计数自建网格。
  - **（t3 交叉后强化）实测帧间隔 α 的缺陷定性**：分母 = 发布间隔 W_k−W_{k−1} 在 4ms 自驱下抖动 ~12–24ms ⇒ 弦扫速 = v·(T/实测间隔) ≠ v——worker 抖动直接变成屏上速度调制，与「高刷流畅度不受损」硬指标冲突。**裁定：α 一律用确定性网格；实现载体推荐新增 `I_A_TICK = i32[6]`（tickIndex 随帧发布，字节 20–63 保留区空闲，与 mode-designer 提案的 I_A_FLAG=i32[5] 同批 additive）**；无 tickIndex 的 MsgState 回退路径才允许实测间隔 α 并降级披露。
- **消费侧硬不变量（P0 的伴生断言，t3 交叉后定稿，全部进 Gate 2）**：
  1. **显示时间单调性**：τ_display 非递减；自适应 D 增大只延长 hold、永不回退（否则每次 D+=1ms 在 3500u/s 下产生 ~3.5 HU 的画面倒退跳变）。τ_display = max(τ_display_prev, now − anchor − D)。
  2. **时钟锚**：主线程 now_m 与 worker 发布时钟 W 跨域，必须一次性锚定 + 漂移刷新（解耦 T7' 有 `extrapClockAnchorMs` 先例，`renderer-main.ts:1032-1035`）；禁止跨域裸比较。
  3. **光标跳变白名单 + 遥测**：重锚/快进/断点帧直出逐次计数（starvation/reanchor 事件表）；平滑手段不可静默退化（D 有界且披露，fallback 率进指标）。
  4. **断点帧禁止跨界插值**：teleport/death/respawn/reset 帧直出 + τ 重锚（I_A_FLAG 机制，防 lerp 扫场伪影）。
- **延迟预算（Δ 的取值，t3 交叉后修正推导）**：J = now − W_latest ∈ [0, T + ε_max)，**与 rAF 相位无关**（发布间隔内 J 随墙钟增长，rAF 只是在其中采样）；零-hold 充要条件 **Δ ≥ T + ε_max**。setTimeout(4) 自驱下 ε_max≈8ms ⇒ Δ≈24ms；**若 worker 改 Atomics.wait(输入槽, timeout=距下个 due tick) 精确唤醒（ε→<1ms），Δ_min ≈ 16.6ms**——这是 r2 框架内唯一可压缩项（解耦 0ms 急轮询 `decoupled-loop.ts:301` 为先例）。缺省 Δ = T + 8ms 守卫 ⇒ 新增可见延迟 ≈ 23.6ms + 一帧合成（144Hz ≈ 7ms）≈ **31ms 恒定**；rAF 频率不影响 Δ 下界，只影响弦采样粒度。Δ 调小则 starvation 上升（卡顿换延迟），调大则延迟增加——**这笔账必须让用户签收**（见 §6 D1）。
- **starvation 语义**：worker 掉帧（补跑 guard<64 封顶，`auth-loop.ts:221`）或发布迟到时，画面冻结在最后真实状态并计数；绝不用外推遮盖。starvation 预算：标称机器 <1 次/10s，单次 <2 tick（Gate 3 判据）。
- **L1 增强（可选，默认关）**：worker 随 tick 帧额外发布 tick 内碰撞子事件（fraction、接触点、法线、子时刻），插值在子事件间分段折线——仍全是已算出的历史值，只是把 tick 内碰撞折弯也回放出来。仅当 L0 验收通过后、且场景矩阵显示 tick 内碰撞折弯造成可见偏差时再启用（与否决权在用户，见 §6 D3）。

## 2. 异常事件判据（压边减速 / 意外碰撞 / 意外运动，量化阈值）

对三模式通用（遥测口径统一才能对比）；单实例模式的目标 = A1–A4 全部为 0（A2 对「同输入重放自身」要求逐位相等）。

### 2.0 合法事件白名单（先立白名单，才谈异常）

teleport / death / respawn / hold 冻结与恢复（`decoupled-loop.ts:273-294`）/ sync-render-state / set-mode 交接 / reset 键 / noclip / land（onGround 上升沿，`auth-loop.ts:171-181`）/ 几何成立的 blocked / duck 切换（空中蹲 origin +18，`player.rs:569` 段）/ 上台阶（STEP_HEIGHT=18）。白名单内的状态突变不计异常，但**必须带事件记录**（白名单外的突变本身就是异常）。
**（t1 交叉后增补三条，phys-researcher A 类清单揭示）**：
- **速度钳制类**：nopre 平地钳 250（`player.rs:907-924`，无 land 沿、连续着地触发）——归因判形 = onGround 态 + 钳制公式精确匹配（|v_h|→250 的比例保持）；bhop 落地钳 275（`player.rs:549-557`）由 land 事件同 tick 覆盖，但钳后速度须与 1.1×maxspeed 公式精确匹配。无此条目时 T2 hard（单 tick 掉速>250 无事件）会误杀合法物理。
- **着地接触修正类**：categorize_position 的 2u 下探吸附 + 速度地面投影（`player.rs:781-832`，出坡带斜上分量的合法来源）——T4 判据的「无碰撞接触」限定词相应改为「无**接触归属**」（ground_contact 归属即可豁免，不要求显式碰撞事件）。
- **T1 参考模型闭式清单**：参考实现必须含 A8 两项（卡死检测 6 tick=93.75ms 常数、跳起延迟 ∈(0,tickDt] 均值 tickDt/2，`player.rs:875-892`）与 A5/A6 钳制公式——否则 replay-self 恒等断言对合法语义误报。

### 2.1 A1 压边减速（硬判据，在线遥测）

- **判据**：单 tick 内 |Δ|v|| > 250 u/s，且不属于 §2.0 白名单任何事件的伴随效应 → 计一次「不可归因减速」。
- 阈值来源：现有 blocked 启发式同款量级（速度>80 且掉速>250 且位移<30%，`auth-loop.ts:188`），但**从「触发校正」降级为「记录计数」**，且必须先做 §2.2 的几何归属复核，防止把合法的坡面 clip_velocity（`player.rs` clip_velocity + OVERBOUNCE_SURF=1.0 保速语义）误报为异常。
- **A2 记账恒等（离线审计，比 A1 严格一个量级）**：以参考实现重放同一输入序列，逐 tick 比对：
  - 空中无接触 tick：|Δv_y − (−800·dt)| ≤ 0.25 u/s（g·dt = 12.5/tick，浮点噪声应 ~1e−9）；
  - 地面 tick：摩擦损失 = max(speed, stop_speed)·4·dt（`player.rs:306-312`，friction=4）可解析预测，|Δv − 预测| ≤ 0.25 u/s；
  - 空中加速 tick：air_accelerate 增量可解析预测（AIR_ACCELERATE=150、wishspeed 钳 30，`player.rs:281-302`），同容差；
  - 位置：|p_tick − p_ref| ≤ 0.5 HU（模型简化误差吸收）；**单实例模式对「重放自身」要求逐位相等（0 容差）**——这是确定性验收，也是模拟台的恒等式基准。
- 用户体验的「压边不可预测减速」在判据上的落点：A1 计数>0 或 A2 违例>0，且时间窗与「贴近边缘（trace 距坡/沿 < 某半径）」相关——场景矩阵把「贴边」做成可控变量即可归因。

### 2.2 A3 意外碰撞（几何复核判据）

- **假落地**：land 事件触发时，用脚底位置向下 GROUND_TRACE_DIST=2 复查，不存在 normal.y ≥ 0.7（STANDABLE_NORMAL）的面 → 计数。
- **幻影阻挡**：blocked 事件触发时，从 prev pos 以同速度重放扫掠 trace，fraction ≥ 1−1e−3（路径无阻挡）→ 计数。
- **碰撞机器噪声**：gate_veto_count（P2 盒-AABB 幻影否决计数器，`world.rs` 常量区、`mod.rs:203` `gate_veto_count()`）单局增量 > 0 → 计数（不判 FAIL，列为「边缘行为噪声指标」，用于三模式对比）。
- 阈值来源：DIST_EPSILON=0.03125（`world.rs:113-114`）作为一切几何容差的基准量级；trace 判定用内核自身 API，避免第二套几何真相。

### 2.3 A4 意外运动（位移/方向/视角越界）

- **位移越界**：|Δp| > |v̄|·dt + 18（STEP_HEIGHT）+ 1 HU，且无白名单事件 → 计数（传送/死亡/锚定拉回都会超界，但它们在白名单内必须带事件；**解耦模式的 alignTickPhys 拉回（TICK_ANCHOR_DIST=64，`decoupled-loop.ts:360-365`）与耦合模式的撤回兜底回滚（`authority-calibrator.ts:269-276`）在第三模式下不存在，若出现同类无事件跳变即异常**）。
- **零输入漂移**：dx=dy=0 且无碰撞接触的 tick 内，水平速度方向旋转 > 15° → 计数（坡面法线切换引发的合法旋转由接触归属排除）。
- **视角越界**：|Δyaw − (−dx·sensitivity·M_YAW)| > 0.05°（M_YAW=0.022，`player.rs` 常量表）→ 计数。
- **校准扰动计数**：耦合 correctFromAuthority 触发次数、解耦 set_velocity 速度覆盖次数（每 64t 一次，`decoupled-loop.ts:371-372`）与锚定次数——三模式对比的「扰动率」指标；单实例模式的设计值为 0。

## 3. 五维对比定稿（单实例 tick vs 耦合 vs 解耦）

每维给出：定义 → 度量方法 → 三模式现状（代码证据）。

### D1 复杂度

- **定义**：为「让画面可信」而存在的协调机制总量。
- **度量**：协调代码行数；PhysWorld 实例数；状态写入方向数；校准通道数。
- 现状：耦合=2 实例（主线程 predPhys 变步长 + Worker 64t 权威）+ 校准器 431 行（`authority-calibrator.ts` 全文）+ 五段 correctFromAuthority（`:174-308`）+ calibrateVelocity + 事件微调 + 反向同步（渲染→权威，`:298-304`）；**写入方向双向**（权威→渲染吸附、渲染→权威 sync-render-state）。解耦=同 Worker 2 实例（1ms phys + 64t tickPhys）+ 443 行循环（`decoupled-loop.ts`）+ 速度强校准（`:371-372`）+ 锚定拉回（`:363-365`）+ 背压 + 慢字段缓存 + 热切换手。单实例=1 实例 + 0 校准通道 + 单向写（worker→SAB）；新增物只有消费侧纯函数插值（规格 ~60 行级）。**度量结论：协调机制从 ~900 行级降到 0，实例数 2→1，写入方向 2→1。**

### D2 输入延迟

- **定义**：输入事件到「含该输入效应的画面」的延迟（m-to-p），分「感知延迟」与「正确性延迟」两个口径。
- **度量**：node 模拟台量确定性分量（tick 排队 + 插值缓冲）；真机分量只进 Gate 3。三模式都报：均值、P99、抖动（方差）。
- 现状：耦合感知延迟≈0（predPhys 当帧吃输入，`renderer-main.ts:954`），但正确性由事后校正兜底——分叉>500/300+yaw≤3°+同向/yawDiff>45° 三条件（`authority-calibrator.ts:291-294`）触发反向同步，视觉表现为橡皮筋/回滚；**本质是「零延迟+不稳定正确性」**。解耦输入进真源 ≤1ms 子步（`decoupled-loop.ts:388-395`）+ 零缓冲外推 ⇒ 延迟≈0，但外推误差在边缘接触处直接可见。单实例=排队 ≤1 tick（均值 7.8ms/最坏 15.6ms）+ 插值缓冲 Δ≈19.6ms + 1 rAF ⇒ **恒定 ~27ms（P99≈均值，抖动≈0）**。
- **结论**：单实例把「0ms 但伴生分叉回滚」换成「恒定 27ms 且正确性恒等」。这是用户裁决项（§6 D1），不是工程优化能消除的——除非重新引入某种渲染推定（违背前提②）。

### D3 确定性

- **定义**：同输入时间线 ⇒ 同状态轨迹（逐位）。
- **度量**：模拟台双跑比对（bit-exact）；变负载（人为 setTimeout 抖动）下再比对。
- 现状：耦合不可确定（predPhys 步长=渲染帧率；校正阈值与墙钟耦合）；解耦不可确定（1ms 子步边界由 setTimeout(0)/wakeup 时序决定，`decoupled-loop.ts:301,383`；输入在子步间的切分随机器负载漂移；tickPhys 校准与锚定阈值依赖时序）。单实例=tick 网格 + 定步长 + 输入按 tick 边界量化 ⇒ **给定输入时间线逐位可复现**（浮点定序由 wasm 保证）。
- **推论**：只有单实例模式能支撑「录输入→重放→逐位 diff」的回归体系；replay 观赏工程（viewer）与模拟台直接受益。

### D4 边缘行为（压边/出坡/高转速）

- **定义**：贴近坡沿、坡面切换、500–3500 u/s 高速场景下异常判据（§2）的触发率与幅度。
- **度量**：场景矩阵逐场景输出 A1–A4 计数与扰动率（Gate 2 产出）。
- 机理预判（待 researcher 备忘证伪/证实）：
  - 耦合：predPhys 与权威在坡面接触的采样密度不同（变步长 vs 64t），接触状态分歧 → 校正吸附（≤300/500 HU 级跳变）与 blocked 误判回路；teleport 语义差（predict 禁传送，`teleport.rs:182-184`）是构造性分歧点。
  - 解耦：每 64t 用 tickPhys 的速度**整向量覆盖** phys（含 vy，`decoupled-loop.ts:369-372`）——tickPhys 在 64t 网格解出的接触结果强行注入 1ms 积分路径，出坡/压边瞬间两实例接触判定不同 ⇒ 速度不连续；位置偏差 >64 HU 时锚定全量拉回 ⇒ 无事件瞬移级跳变。
  - 单实例：接触判定只有一条路径，64 边形语义原样呈现；**残余异常全部可归因内核本身**，模拟台可定位修复——这正是把「双物理机制」从方程里消掉后的可证伪实验。

### D5 维护成本

- **定义**：改一处参数/语义需要同步的位置数、语义陷阱密度、回归手段强度。
- **度量**：参数应用路径数；双写陷阱案例计数；协调代码行数（同 D1）。
- 现状：双实例=参数双路径（W-GAP-1 事故即此类别：`jump_height` 值语义在归一层与对象直传两条路径间反演不一致，`docs/ts-shared.md §3.5`——**解耦模式跳不起来的根因**）；语义陷阱实锤：predict 禁传送、tickRate 耦合+3 偏移 vs 解耦 raw 值（`game/src/worker/main.ts:49-53,222`）。单实例=参数单路径，tickRate 语义唯一（64 基准），回归手段=D3 的逐位重放。
- **结论**：单实例在 D1/D3/D5 是结构性优势（删除量级 ~900 行协调代码）；D2 是明码标价的恒定延迟；D4 是待 Gate 2 数据验证的假设（预期异常归零，若不归零则暴露内核真 bug——仍是收益）。
