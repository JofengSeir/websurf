## 0. 立场总述（先亮结论）

1. **金标准 = 「单实例 + 固定 64 tick + tick 边界采样输入」在给定确定性输入事件流下的逐 tick 状态序列**，记 GOLD(I)。渲染的验收对象是「对 GOLD 的忠实呈现」，不是任何一条连续极限轨迹、更不是耦合预测轨迹（用户 r2 已否决）。用户洞见的 64 边形（单边长短不一）是 **期望输出的一部分**，模拟台的职责是把它量化并确认它被忠实呈现，而不是把它磨平。
2. 我把「忠实反映」拆成 **4 个可测口径 G1–G4**（§4）+ **5 个流畅度指标 M1–M5**（§5），每个口径给出判据、阈值草案、node-wasm 验证手段与 shim 风险。核心可测句式：**「渲染出来的每一个位姿都落在两个相邻已计算 tick 状态之间（含端点），且除此之外不发明任何状态」**——这是「零渲染推定」的可执行定义。
3. 机理归因（团队议题⑤）在模拟台上落为 **G4 双实例 diff 事件清单**：同一输入事件流喂给 耦合复刻线 / 解耦复刻线 / GOLD 线，逐 tick 对齐后枚举每个分叉事件并归因到**具体校准写入路径**（`calibrateVelocity` 灌入 / `decoupled-loop.ts:372` 的 `set_velocity` / `TICK_ANCHOR_DIST=64` 锚定拉回 / `correctFromAuthority` 吸附与反向同步 / 外推越界）。注意：**归因对象是「协调写入 + 语义差」而非「实例数量」本身**（v2.3 按 t4 精化，检验矩阵见 §7-Q2）——这是本备忘可证伪的核心假说。
4. 已核实的一个重要事实（进分歧点清单）：今天 game 的三条 tick 网格**互不相同**——耦合权威线 `fixedDt = 1/(tickRate+3)`（game/src/worker/main.ts:49-50、:173，2026-08-18 用户定调的隐藏偏移），解耦 tickPhys 线用 raw rate（game/src/worker/main.ts:133-134），1ms 真理源在 1000Hz。用户 r2 裁定「tickRate 恒 64」之后，GOLD 用**精确 64Hz**；耦合复刻线应按现状复刻 **67Hz 权威**（这是被归因机制的一部分）。
5. node 直载 wasm 全链路已有先例背书，不是设想：`game/scripts/phys-smoke.mjs`（initSync + readFileSync，重力/跳跃/落地断言）、`game/scripts/phys-rate-parity-v2.mjs`（场景 JSON 构造 + 64/144Hz 对照 + 首碰检测）、`temp/jump-fix.test.mjs` + `jump-fix.bundle.mjs`（esbuild 打包 TS 供 node 跑全链恒等测试）。模拟台 = 把这三类脚本工程化，**不需要任何浏览器**即可完成 G1–G4 与 M1/M2(注入式)/M4/M5；M3 的真实高刷分布需要下一团队的浏览器 pass（本团队禁浏览器，边界如实标注）。

## 1. 被测对象与基准链定义

### 1.1 五条基准链（同一输入事件流，各自消费语义不同）

| 链 | 构成 | tick 网格 | 输入消费语义 | 模拟台中的角色 |
|---|---|---|---|---|
| **GOLD** | 单 PhysWorld，`tick(1/64)` | 精确 64Hz（r2 前提③） | tick 边界取整窗口增量（`auth-loop.ts:127` maxStep=1200·dt·64 语义，饱和截断） | **金标准**，一切 diff 的参照系 |
| **FINE** | 单 PhysWorld，`tick_into(1ms)` | 1000Hz | 逐子步实时消耗（CAS 不限幅语义，`shared-state.ts:403-410`） | 连续极限**参照**（非金标准）：量化 64 离散化的固有代价 |
| **COUPLED-REPLICA** | 权威 phys(67Hz) + 渲染线 predPhys(rAF 节拍) + 校准四件套 | 权威 1/67，渲染 rAF | 双消费者并存：权威 `takeInput` 饱和截断；predPhys 由校准喂 | 现状耦合机制的**复刻**，供 G4 归因 |
| **DECOUPLED-REPLICA** | phys(1ms) + tickPhys(64Hz) + `set_velocity`(:372) + 锚定(:199) | 1000Hz + 64Hz 双线 | `consumeInput` CAS 不限幅 + tickPhys 边界快照 `peekKeys` | 现状解耦机制的**复刻**，供 G4 归因 |
| **NEW-MODE-REPLICA** | 单 PhysWorld 固定 64 tick（t3 草图）+ 主线程历史插值消费 | 精确 64Hz | tick 边界消费（与 GOLD 同语义） | 待验证设计：必须满足 G1 序列恒等 + M1–M5 |

要点：
- **输入以「事件流」为规范**（时间戳 + 键位边沿 + 鼠标增量），不是以 per-tick 快照为规范。各链按自己的消费语义折算（GOLD/tickPhys 用边界快照，FINE/解耦 phys 用逐子步实时）。这样才能公平 diff——差异来自机制而不是来自输入。
- COUPLED-REPLICA 忠实复刻三条现状语义：权威 67Hz 偏移、`calibrateVelocity` 无条件灌入（`src/ts-shared/phys/authority-calibrator.ts:336-358`）、land/blocked 事件推导阈值（`auth-loop.ts:161-164`：速度>80 且单步掉速>250 且实际位移<速度位移×0.3）。**复刻现状 ≠ 认可现状**；diff 数据正是用于裁决它该不该存在。
- 链与链之间除上述差异外**全部同参**：同一份 brush JSON、同一出生点、同一 `set_params` 快照、同一 wasm 产物。

### 1.2 确定性要求（全部链强制）

1. **无随机源**：输入事件流、场景几何、初速全部为版本化常量（JSON 文件入库，坐标优先取 2 的幂/整数，斜率类三角函数值以 16 位有效数字**冻结常量**入库，不在运行时重算——`tan60°` 这类无理数每次重算引入的位差异会污染位级恒等判定）。
2. **出生位置离面 > 2u**：`categorize_position` 的 `GROUND_TRACE_DIST=2` 下探会把贴面出生吸附成着地（教训来自 `game/scripts/phys-rate-parity-v2.mjs` 文件头 v1 教训）。
3. **位级恒等口径**：同一 wasm 产物内两次运行（GOLD×2、跨实例）逐分量 f64 全等；跨 wasm 产物（debug/pkg vs game/pkg）按 |Δ|≤1e-9 相对误差判定（两 crate 的 wasm-bindgen 导出层有意各自维护，见根 `Cargo.toml:5-18` 头注，故不要求跨产物位级）。
4. **产物 pin**：模拟台记录 `websurf_wasm_bg.wasm` 的 hash + 构建命令（`game/package.json` `build:wasm`），结果文件内嵌 hash，保证「结论可复现到同一份二进制」。
5. **时钟注入**：所有复刻线的 `performance.now / rAF / setTimeout` 必须是可注入的合成时钟（固定节拍模式 + 抖动注入模式两种）。固定节拍用于机制隔离（diff 归因时排除时序噪声），抖动注入用于 §5 流畅度压测。

## 2. 场景基元库（参数化口径）

### 2.1 几何与「材质」口径

- 数据格式 = wasm 已消费的 `WasmBrush` JSON（`normal:[nx,ny,nz], dist, min, max, is_ladder, is_solid`，Y-up、法线朝外；构造时序见 `docs/phys.md` §2.1）。**模拟台不发明新几何格式**，只做参数→brush JSON 的确定性展开。
- **材质轴在物理内核坍缩**：物理只认 `is_solid / is_ladder` 二元 + 全局摩擦参数；无 per-material 摩擦。因此场景矩阵的「材质」轴记录的是**表面角色**：ground / wall / ceiling / ladder / trigger，别无他物。这是对外的一个防误解声明：调「材质摩擦」在当前内核是不存在的旋钮。
- 每个基元必须给出：参数表、生成规则（参数→brush 列表的确定性映射）、**标称理论行为**（解析可算的部分算出期望序列，见 §4 G1b）、以及它**主测的异常类别**（对 §4 G2 的事件类型）。

## 3. 三类旋转测试（t2 契约②）

共同驱动口径：鼠标灵敏度在物理端恒 1（`params.ts:58-60`），`M_YAW=0.022`（`player.rs` 常量）；yaw 每 tick 演化 `yaw -= dx·M_YAW`（`mod.rs:225-231`）。测试中的「恒速鼠标」= 每 tick 等像素增量（整数像素，避免采样噪声）。

### 3.1 R-A：沿坡速度 500–3500 u/s 的旋转行为（正面承载用户洞见）

设置：S1 坡（θ=60° 主档，45°/80° 对照）上以 `set_velocity` 直接初始化 v0∈{500,1000,1500,2000,2500,3000,3500}，恒速鼠标 R∈{250,500,1000,2000 px/s}，转向目标 {90°, 360°}；出口构型「悬空」与「接平地」各跑一遍。

量化指标（每格输出，全部可由逐 tick 状态序列算出）：
1. **单边长分布**：逐 tick 位移弦长 L_k=|ΔP_k|，报告 μ/σ/CV/min/max 序列。纯转向时 L_k≈|v_k|·dt，故 **CV(L_k) ≈ CV(|v_k|)** 是「忠实表现」的期望恒等式；任何超出速度差异可解释的弦长波动 = 疑似失真事件（进 G2 计数）。
2. **角步恒定性**：Δθ_k = wrap(yaw_{k+1}−yaw_k) 应恒等于 R·dt·M_YAW（±1e-9）；不恒等 = 输入消费语义被破坏（饱和截断/边界采样错位）。
3. **多边形闭合残差**：360° 转向时 |Σ ΔP_k|（理想 ≈ 0 + dt² 级残差）；速度变化时的解析期望同步给出。
4. **与 FINE 参照的偏差谱**：GOLD vs FINE 的位置/速度差随 tick 的包络——**该偏差是 64 离散化的固有语义，只量化、不做缺陷判定**（用户 r2 前提④的正面落实：方案拟合的对象是 tick 计算本身）。
5. **出坡事件表**：出口构型上的末段速度、离面 tick 索引、离面后 8 tick 内的 G2 事件（压边/意外碰撞）。

### 3.2 R-B：鼠标转向 + 加速组合（速度矢量连续性）

设置：空中（S1 坡上滑行中或纯空中）组合输入：① W+恒定 A/D（扫雪机式转向加速）；② 纯 A/D 空转；③ **甩鼠标 flick**：单 rAF 帧 dx∈{600,1200,2400}px。
判据（逐 tick）：
1. **Δv 物理界**：单 tick 速度变化必须落在 `air_accelerate` 不对称公式界内（`addspeed` 用钳到 `AIR_SPEED_CAP=30` 的 wishspeed、`accelspeed` 用未钳 wishspeed，`player.rs:281-302`）。测量 |Δv_measured − Δv_theory| 超界即记 AE-4 类事件（= 校准注入或实现缺陷的直接证据）。
2. **方向连续性**：速度方向角的单 tick 变化不超理论上限（由 1 的界推出）；无「方向瞬跳」。
3. **flick 饱和语义分叉**：dx=2400px 帧在 GOLD（饱和 1200/step，`auth-loop.ts:127`）与 FINE（CAS 不限幅）下必然分叉——这是**输入消费语义差异**，必须如实量化并在归因表中单列，不许与物理失真混记。
4. **加速全程速度模长曲线**：扫雪机加速段的 |v_k| 序列与理论增益界对照。

### 3.3 R-C：旋转传送装置（yaw 位移型传送）

设置：S7 基元，dest yaw Δ∈{90°,180°,270°}，入速三档，触发体两种长度；变体：冷却内重入、贴坡滑行经过触发体、传送 tick 同时带鼠标输入。
逐条可断言语义（全部来自现有代码时序，模拟台逐条验证）：
1. **传送判定在 tick 序首**：step_core 顺序为 输入应用→noclip→teleport.check→check_death→player_tick（`phys.md` §2.2）→ 传送当 tick 的鼠标 dx 对 yaw 的贡献**被 dest yaw 覆盖**（先应用后被覆写）。断言：yaw(t_k) == dest_yaw 位级。
2. **速度清零**：apply_teleport 清速度（`phys.md` §2.2）→ 断言 |v(t_k)|==0，之后从零重建速度的过程进 G1 恒等。
3. **事件单次**：`PhysEvent::Teleport` 暂存→`take_event` 一次取走；复刻线中渲染线 predPhys **不触发传送**（`predict` 禁传送，`mod.rs:275-295`）→ 耦合线必现「权威已传送 / 预测未传送」分叉→由 `correctFromAuthority` 吸附收拾（`authority-calibrator.ts:174`）——吸附瞬间的位置/速度跳变逐帧计数（这是耦合线「意外运动」的一类直接来源，G4 归因表单列）。
4. **冷却窗口**：0.5s=32 tick 内重入触发体不得二次传送；冷却结束后的重入**必须**传送。
5. **surfing 免触**：贴坡滑行穿越触发体不触发（`teleport.rs` 前置否决）；随后落地路径上 B 路径探针（FOOT_PROBE_DEPTH=8）的触发要单独断言。
6. **yaw 环绕插值安全**：dest yaw 与传送前 yaw 差 >180° 时，渲染插值不得跨传送 tick 做角度 lerp（否则相机甩 350°）——此断言属 §5 M1 的 yaw 分项，R-C 提供其触发输入。

### G3 参数 sweep 响应曲线

- **定义**：以参数为轴批量运行五链，输出响应曲线；**曲线差异是「同一语义在双机制下的响应差」的定量证据**，用于回答「tick 语义本身 vs 机制失真」各占多少。
- **轴**：速度 {500..3500 步 500} × 坡角 {45°,60°,80°} × 链 {GOLD, FINE, COUPLED, DECOUPLED, NEW} × 输入形态 {直行 / R-A 恒速转向 / R-B flick}；附加轴：薄沿厚度 {16,32,64,128}×锚定开关。

- **substep sweep 命题（v2.3 采纳 t3 §5.3 精化，替换我原「出口值不变」表述——原命题按字面不可达且无意义：出口值逐位不变⟹no-op，积分细化的目的恰是改出口值）**：P-sub-1 输入采样不变式（takeInput 每 tick 恰一次 / maxStep 不变 / dx·dy·keys 均分 dt/n、不重采样）；P-sub-2 算子顺序不变式（每子步=完整 step_core 同序列、无重排）；P-sub-3 参数一阶总量守恒+收敛性（friction/accel/gravity 均 dt 一次型；出口值差异完全归因 dt 细分且随 N→∞ 收敛）；P-sub-4 断窗无关。「参数语义不变」= P-sub-1/2/3 成立 + 收敛单调。轴：substep on/off × N∈{1,2,4}；**GOLD=N=1=64Hz 原语义=洞见④金标准**。我方一条补强：**收敛单调性是测量对象不是假设**——以 FINE(1ms) 为 N→∞ 代理，判据 |exit_N−exit_FINE| 随 N 递减；若实测非单调（如 clip 反弹引入振荡收敛），如实出具，属发现而非失败。64→N·64 边形的语义改变**已由 r3-Q3 裁定路径处理（C-2 自决，t3 §12 认领）**：判据=接触事件集恒等——恒等→substep 落默认关 B（预期结果）；不恒等→r4 附数据。本块状态由「待裁依据」转「**执行规格**」。

### 5.1 D 扫描曲线与控制器闭环设计（v2.1 回应 t3 三请托）

**a) P-tick-4 需重定基（对 t3 的反向质疑）**：t3 §8.4 的固定阈值「D<22.5ms → hold>1%；D≥23ms → <1%」与其自身 v1.1 勘误（§11-②：22.5ms/23–28ms 下界**作废**，正确下界 = T + late_max）矛盾——固定数字形式的 P-tick-4 死亡，重定为**参数化预测**：`hold 占比 >1% ⟺ D < T + late_max(实测)`，膝点 D_knee 由扫描实测给出，事后与 t4 两档（16.6/24ms）和 t3 默认 Δ=T+4ms=19.6ms 对照。t3 的 19.6ms 与 t4 的 24ms 之差 = ε_task 尾部余量记账（0 vs 4ms）——这不该靠推导裁决，靠本节扫描裁决。
