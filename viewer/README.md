# WebSurf-viewer — BSP 地图预览与录像回放

> 定位：**纯视觉**——BSP 地图导入 → GLB 场景 + **自由视角**（无物理/碰撞），
> 支持外部传入**人物位置 + 视角**（位姿）实时应用，
> 并支持导入**任意结构的 JSON 录像**、用**可自编写的规则**把它映射成标准帧后回放。
>
> 地图导入构筑场景为最小实现：无 physics Worker、无 mosaic/默认纹理包、无 PVS/LOD、无传送点。
> 录像同样是纯观察：不做物理重演，只按记录播放。

| 文件 | 说明 |
|---|---|
| `crates/wasm/src/lib.rs` | WASM 薄导出层：`BspProcessor` 最小集（metadata / parse_spawn_points / export_glb_with_pakfile_models），**不含 websurf-phys** |
| `src/app.ts` | 主线程装配：BSP → GLB 场景 + 飞行相机 + 位姿三通道 + 侧栏面板 + 录像回放驱动 |
| `src/core/` | 通用层：场景 / 飞行相机 / 位姿 / BSP 加载 / DOM 工具 / 常量 |
| `src/ui/` | 侧栏面板（地图信息 · 量测）+ HUD/引导层/帮助浮层 |
| `src/replay/` | 录像子系统：规则编译 / 导入 / 播放 / 可视化 / 时间轴 / 编辑面板 |
| `test/replay-selftest.ts` | 录像管线 Node 自检（`npm run test:replay`） |

共享 `src/wasm-core/`（BSP 解析/GLB 导出），vmdl patch 同 debug/game/test。

## 快速上手（三步）

> 前置：Node.js ≥ 18；Rust 工具链 + **wasm-pack**（WASM 构建必需，`cargo install wasm-pack`
> 安装，或参考 [官方安装器](https://rustwasm.github.io/wasm-pack/installer/)）。

1. **安装依赖**：`npm install`
2. **构建产物**：`npm run build:wasm`（wasm-pack release → `pkg/`，并拷贝 wasm 到 viewer 根）
   + `npm run build:ts`（typecheck + esbuild 出 `app.js` 与 `parse-worker.js`）；两步可合并为 `npm run build`
3. **启动**：`npm run dev`（即 `python ../src/serve.py 8080 .`）→ 打开 <http://localhost:8080/>；
   或者打包后**双击 `play.cmd`**（自动起服务器 + 开浏览器，见下节）

自检（可选，改录像链路时建议跑）：

| 命令 | 覆盖 |
|---|---|
| `npm run test:replay` | 录像管线 Node 自检：帧探测 / 规则编译 / 播放与 A-B / 坐标系标定求解 / 多轨道 / 大文件进度 |
| `npm run test:smoke` | 真浏览器冒烟（CDP 驱动本机 Edge headless）：页面加载 → 面板渲染 → 导入示例录像 → 播放 / A-B → 多轨迹增删与跟随 → 标定录入求解应用，并断言全程无 console error |

> `test:smoke` 需要另开一个终端跑着 `npm run dev`，并需要 `ws`（`npm i ws`）与 Edge/Chromium；
> 路径可用 `EDGE_PATH` / `WS_PATH` / `SMOKE_URL` / `SMOKE_PORT` 覆盖。

加载地图：还没有地图时点引导层「选择 BSP 地图…」按钮，或直接把 `.bsp` 文件**拖进窗口**
（多文件取首个；解析进行中忽略重复触发）。地图加载后，换图入口在侧栏「地图」页顶部的
「更换地图」（拖拽 `.bsp` 仍全局可用）。本地地图副本放仓库根 `maps/`（gitignored）。

> 只想验证录像链路、手头没有 BSP？打开页面后点侧栏「录像」→「载入示例录像」，
> 会生成一段合成轨迹走完整条导入管线。

## 录像导入与回放

录像页自上而下是三段可折叠分区：**导入与播放**（录像文件 / 轨迹列表 / 起点对齐）、
**对齐与校正**（朝向诊断 / 坐标系标定）默认展开；**高级规则（规则与映射）**（坐标系预设 /
数据定位 / 映射表单 / 脚本）默认收起——控件始终全量在 DOM 中，展开即用。

### 导入

三种方式等效：侧栏「录像」页点「选择 JSON 录像…」、把 `.json` 拖进窗口、或点「载入示例录像」。

**换文件 = 追加一条新轨道**（多轨迹对比）；**改规则后的重新导入 = 更新当前那条**，不会刷出一堆重复轨迹。

- **载入录像即默认第一人称**跟随（要自由观察再切第三人称）
- 有地图时面板「起点对齐」会检查**录像起点与传送起点的距离**——差异大说明坐标系错位或地图不匹配，
  可点「一键锚定到出生点」把轨迹平移对齐（修正 xyz 与地图不符）
- 还不对就换坐标系预设 / 用「坐标系标定」求解完整变换

导入分两步：

1. **探测**：解析 JSON，列出所有「元素为对象的数组」作为候选帧数组，挑最长的那个，
   并展示首帧样例。猜错了就在「帧数组路径」里手填（如 `data.ticks`、`recording.frames`）。
2. **应用规则**：按当前规则把原始帧映射成标准帧，生成 `Clip` 并开始播放。

解析跑在 Worker 里（不卡 UI，且缓存已解析的 JSON，调规则不重解析），定型数组零拷贝回传；
Worker 起不来会自动回退主线程，行为一致。

### 轨迹列表（多轨迹对比）

一次可以加载多条轨迹，同屏对比两次跑法。列表里每条一行：

| 控件 | 说明 |
|---|---|
| 色块 | 该轨迹的配色，按加载顺序自动分配 |
| 名称 | 可直接改名（回车生效） |
| `◉` / `◌` | 显示 / 隐藏这条轨迹 |
| 偏移（秒） | 这条的第 0 帧对应主时钟的哪一刻。**用来对齐起跑时刻不同的跑法** |
| `◎` | 设为跟随目标——第一人称相机与速度读数取自这条 |
| `×` | 移除 |

- 底部时间轴是**主时钟**，统一驱动所有轨道；总长取 `max(偏移 + 各轨道时长)`
- 短的轨道播完会**停在终点**而不是消失，方便看谁先到、差多少
- 第一人称下只隐藏**被跟随**的那条幽灵（它就贴在相机上），其余照常显示——那正是要对比的东西

### 坐标系标定（半自动）

手调轴映射太累时，用对应点让 viewer 自己解。原理是搜索变换 `out = scale · S · P · in + T`
（P 轴置换、S 符号、scale 缩放、T 平移）——轴置换只有 6 种、符号 8 种，给定 (P, S) 后
scale 与 T 有闭式最小二乘解，所以 48 个候选全搜一遍也很快。

操作步骤：

1. **录像侧**：填帧号 → 点「取该帧原始坐标」（按规则里的 posX/posY/posZ 路径读原始值）
2. **世界侧**：从出生点下拉挑一个，或把视角飞到该位置后点「用当前相机位置」；也可手填 XYZ
3. 点「添加对应点」，**至少攒 2 组**（建议 3~5 组、挑分散且确实是同一处的位置）
4. 点「求解」→ 看残差与手性 → 点「应用结果」写入规则并重新导入

求解结果会给这些提示，别忽略：

| 提示 | 含义 |
|---|---|
| 只有 2 组对应点 | 参数刚好定死、无冗余，残差恒为 0 说明不了什么，建议加点 |
| 残差相对点位跨度 > 2% | 极可能有点标错，或这份录像跟当前地图不是同一个 |
| 解是镜像（det −1） | 除非数据源确实是左手系，否则多半是对应点不足导致搜歪 |
| 次优解残差与最优接近 | 对应点不足以区分两组变换，再加几组分散的点 |

> 平移只作用于**位置**，不影响速度——速度是方向量，平移不改变它。

### 规则编辑器

录像格式千奇百怪，所以 viewer 不猜格式，而是把映射规则交给你写。规则编辑器分三层：

**① 坐标系预设**（起点，不是答案；录像文件行的「预设（快捷）」下拉与它同源，
Source / Shavit 录像可先选预设再导入）

| 预设 | 轴映射 | 朝向 |
|---|---|---|
| viewer 原生（Y-up） | (x,y,z)→(x,y,z) | 度；yaw 0 面朝 −Z 逆时针为正；pitch 正为仰视 |
| Source 世界坐标（推荐，与地图一致） | (x,y,z)→(y,z,x) | viewerYaw = yaw + 180；pitch 取反（Source pitch 正为俯视） |
| Shavit 录像（.replay） | (x,y,z)→(y,z,x) | 同 Source 世界坐标：yaw + 180、pitch 取反；ang[0]=pitch、ang[1]=yaw |
| BSP / Hammer 实体（Z-up） | (x,y,z)→(y,z,x) | 同 Source 世界坐标（实体 angles 同为 Source QAngle 约定） |
| 通用 glTF 风格 Z-up（不匹配本项目地图） | (x,y,z)→(x,z,−y) | yaw − 90；pitch 取反 — ⚠ 与本项目几何差 90°，不要用于本项目回放 |

**② 表单**（覆盖绝大多数坐标系差异）

| 组 | 项 |
|---|---|
| 位置 | X/Y/Z 字段路径、轴映射（输出轴取输入哪个轴）+ 符号、单位缩放、**原点平移**、是否眼位 |
| 朝向 | yaw/pitch/roll 字段路径、角度单位（度/弧度）、yaw 系数与偏移、pitch/roll 符号 |
| 速度 | VX/VY/VZ 字段路径（留空即无速度显示；沿用位置那套轴映射与缩放） |
| 时间 | 等间隔 tick（t = 序号 / tickrate）或帧内时间字段（秒/毫秒/tick 数） |

字段路径写法：`pos[0]`、`ang[1]`、`data.origin.x`、`tick`——支持 `.` 与 `[n]` 混写。

**③ 规则脚本（逃生舱）**

表单只是**生成器**，生成出来的是一段可读的 JS：

```js
// 由「导入规则」表单生成 —— 可直接改写（改写后表单改动不会再覆盖本段代码）
// raw  原始帧对象   i 帧序号
// H    H.get(raw,"pos[0]") 取路径  H.num(v) 转数字  H.wrap(度) 归一[0,360)
//      H.clampPitch(度) ±89 限幅  H.deg(弧度) 转度  H.EYE 站立眼高 64.09
(raw, i, H) => {
  const _ix = H.num(H.get(raw, "pos[0]"));
  const _iy = H.num(H.get(raw, "pos[1]"));
  const _iz = H.num(H.get(raw, "pos[2]"));
  const _yaw = H.num(H.get(raw, "ang[1]"));
  const _pitch = H.num(H.get(raw, "ang[0]"));
  const _vx = H.num(H.get(raw, "vel[0]"));
  // …
  return {
    t: i / 128,
    pos: [_ix, _iy, _iz],
    ang: [H.wrap(_yaw), H.clampPitch(_pitch), 0],
    vel: [_vx, _vy, _vz],
  };
}
```

直接改它就是最终Authority——改完打上「已手工改写」标记，表单不再覆盖；
想回到表单驱动就点「从表单重新生成」。规则可以「导出规则」存成 JSON 复用，
下次「导入规则」载入。

标准帧约定（`Clip` 里存的就是这个）：

- `t`：秒，单调递增
- `pos`：**人物脚底**位置，viewer 世界坐标 **Y-up**
- `ang`：`[yaw, pitch, roll]` 度；yaw 0 面朝 −Z、逆时针为正、归一到 [0,360)；pitch ±89° 限幅
- `vel`：世界速度 `[vx,vy,vz]`，缺失为 `null`

出错时会明确报出**第几帧、什么问题、原始帧长什么样**——例如
`第 0 帧的位置不是三个有效数字（[null,null,null]）——检查位置字段路径与轴映射`。

### 播放控制（底部时间轴）

| 控件 | 说明 |
|---|---|
| 播放/暂停、停止 | 空格以外：`K` 键也可切换播放 |
| `◀ 帧` / `帧 ▶` | 逐帧步进，快捷键 `,` / `.` |
| 进度条 | 拖动定位 |
| 倍速 | 0.1× ~ 4× |
| 循环 | 默认开 |

| 轨迹线 / 幽灵 | 显示开关；第一人称下只隐藏**被跟随**的那条幽灵，其余保留以便对比 |

## 故障排查

| 现象 | 原因 / 处理 |
|---|---|
| 页面显示「viewer 初始化失败」，提示缺 `app.js` / wasm | 未构建就打开了页面：在 `viewer/` 目录依次运行 `npm install` → `npm run build:wasm` → `npm run build:ts` 后刷新 |
| 状态行报 `fetch wasm → 404` 或「缺少 WASM 产物」 | 缺 WASM 产物：先运行 `npm run build:wasm`（生成 `pkg/` 并拷贝 wasm 到 viewer 根）再刷新 |
| 「无法创建 WebGL 渲染上下文」 | 浏览器不支持/禁用了 WebGL、硬件加速关闭或显卡驱动过旧——换最新版 Chrome / Edge / Firefox 并开启硬件加速 |
| `npm run dev` 报端口占用 | 8080 被其他进程占用：结束占用进程，或换端口启动 `python ../src/serve.py 8090 .` 后访问对应端口 |
| 按 `Ctrl` 下降时误触浏览器关闭标签页（Ctrl+W） | 浏览器级快捷键页面无法拦截：下降改用 `C` 键，或在 Firefox 中使用（按键拦截更宽松） |
| 状态行闪现「鼠标锁定失败，请再点击一次画布重试」 | 指针锁定偶发失败（如 Esc 后立即点击）：按提示再点一次画布即可，约 3s 自动恢复原文本 |
| 引导层报「这不是有效的（或暂不支持的）BSP 地图文件」 | 文件损坏或为暂不支持的 BSP 版本；确认选择的是 `.bsp`（拖入非 `.bsp`/`.json` 文件也会被拒绝并提示） |
| 导入录像报「没能在 JSON 里自动找到『元素为对象的数组』」 | 帧数组藏得太深或首元素不是对象：展开「高级规则」组，在「数据定位」里点「探测 / 重新探测」后从下拉里选，或在「帧数组路径」手填 |
| 导入成功但画面里看不到轨迹 / 轨迹在地图外 | 坐标系映射不对：换坐标系预设、调轴映射与 yaw 偏移，或直接在脚本里算；HUD 会提示轨迹是否整段落在地图包围盒外 |
| 录像朝向反了 / 方向不对（能播但朝向怪） | 「录像」→「朝向诊断」：运行诊断看 θ_view，不一致就点「一键修正朝向」（自动调 yaw 偏移并重导）；pitch 符号是约定固化项，一般不用动 |
| 导入报「第 N 帧的 X 不是三个有效数字」 | 字段路径写错或该帧缺字段：对照面板里的「首帧样例」修正路径 |
| 录像里有速度但时间轴显示「速度 —」 | 规则里 VX/VY/VZ 路径留空了：展开「高级规则」组，在「速度（可选）」里填上路径即可 |
| 播放时画面不动 / 时间轴不推进 | 检查是否暂停（`K` 切换）、A-B 区间是否被框成了极短的一段、倍速是否 0.1× |
| 改一次规则就多出一条轨迹 | 不该发生——改规则是**替换**当前轨道。若出现，说明这份文件被当成新文件重新载入了（换文件才追加） |
| 两条轨迹对不齐 | 用轨迹列表里的「偏移」把后起步的那条往后挪；偏移单位是秒 |
| 标定求解后轨迹反而更歪 | 看求解结果的提示：残差大 / 镜像 / 次优接近，多半是对应点标错或不够。确认录像和地图是同一张 |
| 长时间录像导入后进度条不动 | 约每 2% 更新一次；29 万帧（67 tick/s × 12h）解析本身要几秒，属正常。帧数 ≥ 10 万时会提示关掉自动重导入 |

## 规模参考

| 场景 | 帧数（67 tick/s） | 定型数组内存 | JSON 文本（估） |
|---|---|---|---|
| 40 分钟 | 160,800 | ~7 MB | ~24 MB |
| 12 小时 | 289,440 | ~13 MB | ~43 MB |

这个量级**不需要分块流式**：解析跑在 Worker 里不卡 UI，轨迹线自动抽稀到 4 万点，
进度约每 2% 回传一次。超过 10 万帧时建议关掉「改完自动重新导入」，改完手动点「应用脚本」。

## 位姿（人物位置 + 视角）传入三通道——应用即生效

1. **URL 查询参数**（页面加载即应用）：
   `index.html?pos=100,50,200&ang=45,10`
2. **URL hash**（`hashchange` 实时应用，外部脚本改 `location.hash` 即响应）：
   `#pos=100,50,200&ang=45,10`
3. **JS API**（直接调用，响应最快）：
   ```js
   window.viewer.setPose({ pos: [x, y, z], ang: [yaw, pitch] });   // 数组或 {x,y,z}/{yaw,pitch} 对象均可
   const p = window.viewer.getPose();                              // { pos: [x,y,z], ang: [yaw,pitch] }
   const r = window.viewer.replay;                                 // 只读内省（见下）
   ```

`window.viewer.replay` 是只读内省，供外部脚本与自动化检查当前状态：

| 字段 | 含义 |
|---|---|
| `trackCount` | 当前加载了几条轨迹 |
| `duration` | 主时钟总长（秒）= `max(偏移 + 各轨道时长)` |
| `time` / `playing` | 主时钟当前时间与是否在播 |
| `followId` | 被跟随的轨道 id（第一人称相机与速度读数取自它） |
| `sceneObjects` | 场景根对象数（轨迹线/幽灵/标记是否真挂进去了） |
| `orientation` | 最近一次「朝向诊断」的结果 `{ angleDeg, srcAngleDeg, displacement, verdict: 'pass'\|'fix'\|'skip', … }`；未运行过为 `null` |

### 朝向诊断与一键修正（Shavit 录像专用断言）

Source 系录像（Shavit .replay 等）常遇到「轨迹能播但朝向反了/方向不对」。面板「录像」→
「**朝向诊断**」分区只凭录像自身数据判定（不依赖地图/出生点）：

- **判据（保角自洽）**：首段轨迹**移动方向**在源空间与 viewer 空间分别与**首帧朝向**算夹角，
  二者相等（|θ_view − θ_src| ≤ 1°）即判定映射链自洽（PASS）、yaw 补偿与轴映射配套；
  注意**绝对夹角不作失败条件**——surf 起跑常侧身蹭速，正身夹角可 >35°。
  位移不足（< 24 HU，起跑前站立）或起跑即转向（Δyaw ≥ 45° 且窗口过短）判「数据不足」（SKIP，不算失败）；
  录像带 `preFrames` 时自动用 run 起点附加窗口复核。
- **一键修正**：不自洽时点「一键修正朝向」，在 yaw 偏移候选 {现状, +90°, −90°, +180°} 中取
  与源空间自洽（|θ_view − θ_src| ≤ 1°）的应用，重新导入；所有候选都不自洽（如轴映射与规则整体
  不配套）则提示目视确认 / 跑坐标系标定（pitch 不参与自动修正：Source pitch 正=俯视、viewer 正=仰视
  是约定固化项，水平移动也无法验证 pitch）。
- 自动化：`window.viewer.replay.orientation` 暴露最近诊断结果（冒烟测试断言走此钩子）。

> 局限：位置正确性（轨迹是否与地图贴合）不属此断言，由「起点对齐」与「坐标系标定」负责。

### 位姿约定（与 game 一致）

- `pos` = **人物脚底位置**（Y-up 世界坐标，GLB 空间）；相机眼位 = `pos + 眼高 64.09`
- `ang` = `[yawDeg, pitchDeg]`：yaw 0 = 面朝 −Z，正方向逆时针（俯视），即 game 的
  cs-movement yaw 约定（BSP yaw 经 `bspYawToCsYaw = (270 - yaw) % 360` 转换，出生点初始视角已自动转换）；
  pitch 正 = 仰视，±89° 限幅
- 无外部位姿时初始视角 = 推荐出生点（`info_player_start` 优先）
- **录像第一人称回放期间位姿通道被忽略**（相机由播放器驱动）；切回第三人称或清空录像即恢复
