本技能收集 WebSurf 仓库（Windows + PowerShell）反复撞过的墙：假绿、假「功能已删」、编码与行尾、输出截断、沙箱边界。目标：每堵墙只撞一次。

**边界**：本技能只讲「怎么干活不撞墙」，**不是事实来源**；事实回源码、构建脚本与命令输出。

## 1. Quick start（两条命令）

~~~bash
git status --short -uall     # 开工：看有没有别人的在途改动
node --check <脚本>          # 改完 JS：先做语法检查
~~~

## 2. 三条最贵的坑

| # | 坑 | 后果 | 规避 |
|---|---|---|---|
| 1 | 长输出被**静默截断成「尾部」** | 直接解析 stdout 拿到残缺集合，据此下的结论全错 | 大输出先落盘再读；**先断言规模（总数）再判读内容** |
| 2 | 「文件不在 git 树上」≠「功能已删除」 | `git grep` / `git ls-files` 只覆盖**已跟踪**文件 | 判存在性走**全工作区索引**（含未跟踪） |
| 3 | basename 存在性检查批量假阴性 | 正则分支 `js` 先于 `json` 命中，把 `package.json` 切成 `package.js` | 正则**最长后缀优先**：`d\.ts|json|mts|mjs|cjs|ts|js|rs|md|cmd` |

## 3. 为什么是这些坑

共性：**失败时不报错，只给一个看起来合理的错答案**——截断的输出像完整输出，`git grep` 0 命中像「已删除」，`existsSync` false 像「不存在」。因此本仓的规矩是**先断言规模、再判读内容**，而不是拿到结果就用。

## 4. 作业流程（按场景）

1. **跑命令取证据**：大输出用 Node 写文件再读（`execFileSync(cmd, args, { encoding: 'utf8', maxBuffer: 64*1024*1024 })`），并**先断言规模**（如 `git rev-list --count HEAD`）再看内容。互不依赖的检查合并进同一段程序跑完再打印摘要，比一条一回合省一个数量级。
2. **判「某物是否还在」**：走**全工作区文件索引**（含未跟踪），不要用 `git grep` 的 0 命中下结论；生成物 / 本地物清单见 REFERENCE §2。
3. **跑待办 / 验收判据**：先确认判据引用的路径**真的存在**，再用「证据」文件本身复核该模式是否仍命中——判据可能指错路径 / 指错目录，会把条目**永久假结案**。
4. **准备提交**：`git status --short` → 只 `git add` 自己的文件 → 验证与提交 `&&` 串联，红灯即终止。
5. **改门禁 / 做注入验证**：先断言「确实改了字节」，再断言该拦的拦住了、**该放行的仍放行**。

## 5. 对错示例

| WRONG | RIGHT |
|---|---|
| `git grep "某函数"` 返回 0 命中 ⇒ 结案「功能已删除」 | 先查该物是否属生成物 / 本地物，再用全工作区索引（含未跟踪）复核 |
| `existsSync('package.json')` 为 false ⇒ 「文件不存在」 | 用全仓 basename → 路径表判定，或正则分支**最长后缀优先** |
| 验证和提交写成 `;` 连接，红灯照样提交 | 写成 `&&`，红灯即终止 |

## 6. 收尾 checklist

- [ ] 大输出：先断言了规模，再判读内容。
- [ ] 存在性判断：用全工作区索引 / basename 表，不是 `git grep`。
- [ ] 提交前列过 `git status --short`，别人的在途改动原样保留。
- [ ] 没有用 `git checkout -- <文件>` 清理工作区。
- [ ] 改过 `.cmd` / `.bat` / `.ps1`：确认行尾是 CRLF，并实跑过一次。
- [ ] 结论落到了 `文件:行号`；落不到就标 `[待确认]` 并说明缺什么。
